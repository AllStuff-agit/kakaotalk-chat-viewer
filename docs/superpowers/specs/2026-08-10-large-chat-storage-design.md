# 대용량 채팅 저장 및 탐색 설계

## 목표

채팅 파일을 서버로 전송하지 않고 브라우저 안에서 처리한다. 파일 전체 문자열, 전체 메시지 배열 또는 전체 DOM을 메모리에 올리지 않는다. 파일 크기에 인위적인 상한은 두지 않으며, 실제 한계는 브라우저가 제공하는 로컬 저장 공간으로 정한다.

## 데이터 흐름

`parser.worker.js`가 `File.stream()`과 `TextDecoder`로 파일을 순차 읽는다. 줄 경계와 여러 줄 메시지 상태만 유지하고, 완성된 메시지는 일정 개수씩 IndexedDB에 저장한다. 메인 스레드에는 제목, 저장 날짜, 메시지 수, 참여자 통계, 날짜별 첫 인덱스만 전달한다. 진행률을 표시하고 실패하거나 저장 공간이 부족하면 원인을 사용자에게 알린다.

IndexedDB에는 현재 대화의 메시지를 5,000개 단위 청크로 저장하고 각 메시지에는 연속 숫자 인덱스를 둔다. 화면 조회는 필요한 청크에서 최대 400개만 반환하고 검색은 청크 단위로 역순 탐색한다. 새 파일을 가져올 때 기존 데이터는 정리하며, 모든 데이터는 해당 브라우저에만 남는다. 별도 서버나 의존성은 추가하지 않는다.

## 표시와 이동

`ChatRenderer`는 데이터 배열 대신 비동기 범위 조회 함수를 사용한다. 현재 화면 주변 최대 400개 항목만 가져와 렌더링한다. 고정 크기의 가상 스크롤 트랙을 전체 메시지 인덱스에 비례시켜 브라우저의 최대 스크롤 높이 제한을 피한다. 빠르게 스크롤하면 오래된 조회 응답을 폐기하고 가장 최근 위치만 그린다. 검색 및 날짜 선택은 저장된 메시지 인덱스로 같은 스크롤 위치에 이동한다.

## 검색

검색은 Worker가 IndexedDB를 최신 메시지부터 역방향으로 순회한다. 대소문자를 구분하지 않고 최근 결과 최대 200개를 반환하며, 전체 결과 DOM을 만들지 않는다. 새 검색이 시작되면 이전 검색을 취소한다. 표시할 텍스트는 HTML로 이스케이프한 뒤 일치 부분만 강조한다.

## 오류 처리와 검증

지원하지 않는 브라우저, 읽기 실패, IndexedDB 오류, 저장 공간 부족을 구분해 안내한다. 자동 검사는 청크 경계의 여러 줄 메시지, 저장·범위 조회·역방향 검색, 최대 400개 렌더링, 오래된 비동기 조회 폐기를 확인한다. 브라우저 검증은 대용량 합성 파일에서 파싱 중 UI 응답, 매우 빠른 상·하 스크롤, 검색 및 날짜 이동을 확인한다.
